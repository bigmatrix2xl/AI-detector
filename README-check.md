# Проверка текстов детектором — как это подключено

Скрипт `check.js` прогоняет готовый кейс или статью через движок этого детектора
и печатает отчёт в терминал. Нужен, чтобы Claude проверял текст сам, до того как
отдать документ.

## Запуск

```bash
node check.js файл.docx              # строгий профиль (по умолчанию)
node check.js файл.docx balanced     # другой профиль
node check.js файл.docx strict json  # полный JSON, как из браузерной версии
```

Работает и с .txt / .md.

Движок ищется автоматически: сначала рядом со скриптом (если `check.js` лежит
в корне репозитория — это рабочий вариант), потом в подпапке `AI-detector`.
Если движок в другом месте — укажите путь:

```bash
AI_DETECTOR_DIR=/путь/к/AI-detector node check.js файл.docx
```

## Что скрипт выбрасывает из проверки

Из .docx берётся только публикуемый текст. Не попадают в проверку:

- абзацы, целиком набранные курсивом (служебные строки, alt, пометки дизайнеру,
  анкоры перелинковки);
- строки, начинающиеся с `alt:`, `Дизайнеру:`, `Анкор`, `Ссылка`, `Title`,
  `Description`, `URL` и с длинного тире (служебные пометки в конце).

Поэтому вручную вычищать документ перед прогоном больше не нужно — скрипт делает
это сам, читая курсив прямо из разметки Word.

## Целевые пороги для проекта «Доминион»

- AI-сигнал в строгом профиле: **≤35/100**
- Сегментов `AI` и `LIKELY_AI` в теле текста: **0**
- Метрика «Конкретика и опыт» остаётся красной — это норма. Она требует
  коммерческих цифр и дат, которых мы не публикуем. Подтягивается только
  цитатами интерфейса и живыми деталями проекта.

## Известное ложное срабатывание

Слово «производитель» во всех падежах засчитывается как канцелярит «производится».
Причина в `js/detector.js`, функция `phraseToRegex`: для слов от 7 знаков она
отрезает 2 последних буквы и разрешает хвост до 4 букв, поэтому «производит» +
«елей» совпадает. Для однословных фраз хвост стоит сделать короче.
